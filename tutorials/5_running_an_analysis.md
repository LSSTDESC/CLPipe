# Running an analysis

The previous tutorials run each step of the pipeline alone. In an analysis,
the steps run one after the other from a run directory, with a few
configuration files and a job script. This page follows the cosmoDC2
redMaPPer baseline analysis in
`examples/cosmodc2_redmapper/baseline/cosmodc2_redmapper_full_analysis/run_in2p3_both`.
To try a full run on a small sample first, use `examples/cosmoDC2-1deg2`,
whose steps before the sampling take a few minutes. The
[main README](https://github.com/LSSTDESC/CLPipe#readme) lists the other
examples.

## What is in a run directory

```
run_in2p3_both/
    TXPipe.yml                pipeline file of the TXPipe stages
    TJPCov.yml                pipeline file of CLPCovariance
    Firecrown.yml             pipeline file of CLPFirecrown
    config_in2p3_both.yml     options of every stage, one section per stage
    launch_job_all_in2p3.sh   job script that runs everything
```

The pipeline is split in three files because TXPipe and the CLPipe stages run
in different environments, and because the chain is sampled by CosmoSIS after
the last file has run.

## The pipeline files

The pipeline files are read by [ceci](https://github.com/LSSTDESC/ceci). Here
is `TJPCov.yml`, with comments added.

```yaml
id: TJPCov
modules: clpipe                  # package where ceci finds the stages
stages:
  - name: CLPCovariance
    nprocess: 1
inputs:                          # files that are not produced by a stage of this file
    fiducial_cosmology: /sps/lsst/groups/clusters/cl_pipeline_project/TXPipe_data/cosmodc2/fiducial_cosmology.yml
    clusters_sacc_file: /sps/lsst/groups/clusters/cl_pipeline_project/TXPipe_data/cosmodc2/outputs-full-2026//cluster_sacc_catalog.sacc
config: ./config_in2p3_both.yml  # options of the stages
output_dir: ./outputs_both
log_dir: ./logs_both             # one log per stage
resume: false                    # true skips the stages whose outputs already exist
```

Each stage declares the tags of the files it reads and writes. When a stage
writes a file that a later stage of the same file reads, ceci connects them
through the tag. Between two pipeline files the connection is made by path:
`Firecrown.yml` lists `./outputs_both/clusters_sacc_file_cov.sacc`, written by
`TJPCov.yml`, as its `clusters_sacc_file_cov` input.

## The configuration file

The configuration file has one section per stage, named after the stage, for
the TXPipe stages and the CLPipe ones alike. An option that is not given takes
the default of the stage. The options of
[`CLPCovariance`](https://lsstdesc.org/CLPipe/source/clp_covariance.html)
and [`CLPFirecrown`](https://lsstdesc.org/CLPipe/source/clp_firecrown.html)
are listed in the documentation, and the tutorials of these stages show the
sections used in this analysis.

## Launching the run

From the run directory, submit the job script with `sbatch
launch_job_all_in2p3.sh` (`launch_job_all_nersc.sh` at NERSC). Without the
batch options, it does the following.

```bash
conda activate /sps/lsst/groups/clusters/cl_pipeline_project/conda_envs/txpipe_clp
export PYTHONPATH=/path/to/CLPipe:/path/to/TXPipe:$PYTHONPATH
ceci TXPipe.yml

conda deactivate
conda activate /sps/lsst/groups/clusters/cl_pipeline_project/conda_envs/firecrown_developer_clp
export PYTHONPATH=/path/to/CLPipe:$PYTHONPATH
ceci TJPCov.yml
ceci Firecrown.yml

cd ./outputs_both
mpirun -n ${SLURM_NTASKS} cosmosis --mpi sampler_file.ini
```

The `PYTHONPATH` lines point to the TXPipe and CLPipe checkouts used by the
run. CLPipe is not installed in the shared environments, so its path is
needed there. If you installed CLPipe in your own environment with
`pip install .`, as in the main README, you can remove it. The last line
samples the likelihood with the files generated by `CLPFirecrown`.

## Outputs

The TXPipe stages write to the `output_dir` of `TXPipe.yml`. In this analysis
it is a shared folder, so that several runs can start from the same
measurements. The CLPipe stages and CosmoSIS write to `outputs_both`.

| File | Written by |
|---|---|
| `clusters_sacc_file_cov.sacc` | `CLPCovariance`, the data vector with its full covariance |
| `clusters_sacc_file_cov_gauss.sacc`, `clusters_sacc_file_cov_SSC.sacc` | `CLPCovariance`, the Gaussian and super-sample covariance terms from TJPCov |
| `likelihood_file.py`, `sampler_file.ini`, `priors_file.ini` | `CLPFirecrown`, the Firecrown likelihood and the CosmoSIS files |
| `output_rp/number_counts_samples.txt` | CosmoSIS, the chain |

## Running part of the analysis again

- With `resume: true` in a pipeline file, ceci skips the stages whose outputs
  already exist.
- A single stage can be run from the command line, as explained in the main
  README.
- To sample again without rerunning the stages, run `cosmosis sampler_file.ini`
  from the output folder. Adding `-p runtime.sampler=test` evaluates the
  likelihood once, which is a quick way to check the setup.
- The sampler and its settings are options of `CLPFirecrown` (`sampler`,
  `emcee_walkers`, `emcee_samples`, the `polychord_*` options and `filename`
  for the chain). With `resume: true` in the `CLPFirecrown` section, CosmoSIS
  continues an existing chain instead of starting a new one.

## Setting up a new run

The simplest way is to copy a run directory and change its paths and options.
For several runs that differ by a few values (site, data, binning),
`examples/template/configure_pipeline.py` writes all the files of a run from
templates and a short list of parameters. Its README explains how.

## After the chain

- `examples/cosmodc2_redmapper/plot_samples.ipynb` makes the triangle plots of
  the paper with `clpipe.utils.cosmosis_mcmc_plots`, which can also save a
  chain as a compact FITS file.
- [4_theory_prediction.ipynb](4_theory_prediction.ipynb) compares the model with
  the data at any point of the chain, for instance the best fit.
